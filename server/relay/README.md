# Посредник до Telegram

Из сети сервера нет маршрута до `api.telegram.org` — проверено: не отвечают
ни 443, ни 80, ни 8443, то есть блокировка на уровне адресов. Настройками
сервера это не обходится, нужен посредник в сети, откуда телеграм доступен.

Cloudflare с сервера доступен, поэтому используется он.

## Развернуть

1. Завести бесплатный аккаунт на `dash.cloudflare.com`
2. Раздел **Workers & Pages** → **Create** → **Start with Hello World** → **Deploy**
3. Открыть редактор (**Edit code**), заменить содержимое на `telegram-worker.js`
   из этой папки, нажать **Deploy**
4. Скопировать адрес вида `https://имя.поддомен.workers.dev`
5. Проверить: открыть его в браузере — должно ответить `ok`

## Подключить

На сервере в `server/.env`:

```
TELEGRAM_API_BASE=https://имя.поддомен.workers.dev
```

Затем:

```bash
cd /opt/it-optimization/server
docker compose -f docker-compose.prod.yml up -d api
```

Проверить, что бот ожил:

```bash
docker compose -f docker-compose.prod.yml logs api --tail 20 | grep -i бот
```

Ошибки `Connect Timeout Error` должны исчезнуть.

## Что стоит знать

**Токен проходит через воркер.** Bot API передаёт его в пути запроса, иначе
никак. Воркер его не хранит и не логирует, но сам факт учитывайте: доступ к
аккаунту Cloudflare равен доступу к боту. Если это неприемлемо — остаётся
вариант со сводкой через GitHub Actions, но тогда пропадают команды и
мгновенные уведомления.

**Лимиты бесплатного тарифа** — 100 000 запросов в сутки. Бот при опросе раз
в несколько секунд расходует около 30 000, то есть с запасом.

**Если блокировку снимут** — верните `TELEGRAM_API_BASE=https://api.telegram.org`
и перезапустите контейнер. Больше ничего менять не нужно.
